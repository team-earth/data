# GOSR Knowledge Graph MCP Server

## Overview

This Model Context Protocol (MCP) server provides intelligent access to **GOSR** (Goal ← Obstacles ← Solutions ← Resources) knowledge graphs generated by the AI-Powered Problem Structuring Toolkit. The server enables LLMs to query and analyze complex societal challenges through structured endpoints rather than loading massive JSON files into context.

GOSR facilitates **alignment through transparency**, not coordination through control. This MCP server makes problem structures and existing resources visible to all stakeholders, enabling voluntary self-organization around community challenges.

## GOSR Framework Structure

The GOSR framework organizes complex problem-solving data hierarchically:

```
Goal: "Building Community Resilience Against Extremism" 
(future_picture from config.yaml)
│
├── Obstacle: "Lack of Comprehensive Approach"
│   (generated by g2o.py from root_question)
│   │
│   ├── Solution: "Education and awareness programs"
│   │   (generated by o2s.py for each obstacle)
│   │   │
│   │   ├── Resource: Canadian Centre for Gender and Sexual Diversity
│   │   │   (generated by s2r.py, cleaned by raw2resources.py)
│   │   ├── Resource: [organization details, contact info, description]
│   │   └── Resource: [additional education resources]
│   │
│   ├── Solution: "Encouraging community engagement" 
│   │   ├── Resource: Neighbourhood Toolkit Program
│   │   ├── Resource: Crime Prevention Ottawa
│   │   └── Resource: [additional engagement resources]
│   │
│   └── [additional solutions with mapped resources]
│
└── [additional obstacles from major_theme_obstacles in config.yaml]
```

**Key GOSR Properties:**
- **Hierarchical Structure**: Goal → Obstacles → Solutions → Resources  
- **AI-Generated**: Scripts accelerate traditional 3-6 month stakeholder process
- **Transparent Mapping**: Makes invisible problem structure visible
- **Resource-Grounded**: Links abstract solutions to concrete community assets

## 🏗️ Data Pipeline & Schema Evolution

### Current Status
- **Data Format**: Mixed JSON structures with manual parsing logic
- **Validation**: Runtime error handling without formal schema
- **Generation**: Python scripts with LLM interaction (external to this repo)
- **Maintenance**: Manual fixes for inconsistent data structures

### Industry Standard Migration Plan
We're moving toward industry-standard practices for robust, maintainable data pipelines:

**Target Stack:**
- **Pydantic Models**: Type-safe schema definition for GOSR structures
- **JSON Schema Validation**: Formal schema enforcement at generation time
- **Structured LLM Output**: Using libraries like `instructor` or `langchain` with Pydantic
- **Automated Pipeline**: Python-based generation with built-in validation

**Benefits:**
- **Type Safety**: Catch schema issues at generation time, not runtime
- **Consistency**: All datasets follow identical, validated structure
- **Maintainability**: Schema changes propagate automatically
- **Developer Experience**: IDE support, auto-completion, and clear error messages

**Implementation Approach:**
1. Define Pydantic models matching current hierarchical structure
2. Create validation layer for existing data
3. Migrate generation scripts to use structured output
4. Gradually normalize inconsistent datasets

*This evolution will maintain full backward compatibility with the current MCP server while making future data generation more reliable and maintainable.*

## 🚀 MINIMAL VIABLE PRODUCT (MVP) ENDPOINTS

**Goal**: Get basic functionality working immediately with simple JSON queries from GOSR output files.

### Core Query Functions

#### `query_knowledge_graph`
```python
query_knowledge_graph(
    query_type: str,           # "find_resources_by_keywords" | "get_resources_by_ids" | "get_solutions_for_keywords"
    keywords: list[str] = None,        # ["youth", "mental health", "employment"]
    resource_ids: list[int] = None,    # Resource IDs from resources.json
    obstacle_theme: str = None,        # Top-level obstacle from major_theme_obstacles
    limit: int = 5             # Maximum results to return
) -> list[dict]
```

**Data Sources**: 
- `r.json` (hierarchical resource tree from s2r.py)
- `resources.json` (cleaned/normalized by raw2resources.py)
- `s.json` (solutions mapped to obstacles by o2s.py)
- `o.json` (obstacles generated from g2o.py)

**Example Usage:**
```python
# Find youth mental health resources from GOSR data
query_knowledge_graph(
    query_type="find_resources_by_keywords",
    keywords=["youth", "mental health"],
    limit=3
)

# Get resources for specific obstacle theme
query_knowledge_graph(
    query_type="find_resources_by_obstacle",
    obstacle_theme="Urban anonymity",  # from config.yaml major_theme_obstacles
    limit=5
)
```

#### `get_resource_details`
```python
get_resource_details(
    resource_id: int           # Resource ID from resources.json
) -> dict
```

Returns normalized resource data including:
- name, description, organization
- address, email, website (cleaned by raw2resources.py)
- validation status (from recheck_resource_urls.py if run)

#### `search_solutions_by_obstacle`
```python
search_solutions_by_obstacle(
    obstacle_name: str,               # Obstacle from o.json
    solution_keywords: list[str] = None   # Filter solutions by keywords
) -> list[dict]
```

#### `get_gosr_hierarchy`
```python
get_gosr_hierarchy(
    level: str = "full",              # "goal" | "obstacles" | "solutions" | "resources" | "full"
    obstacle_filter: str = None       # Specific obstacle theme to focus on
) -> dict
```

Returns the complete GOSR structure or filtered subset.

## Data Sources & File Structure

### GOSR Project Files
Generated by the AI-Powered Problem Structuring Toolkit:

#### Configuration
- **`config.yaml`**: Project configuration including:
  - `future_picture`: Goal statement (e.g., "Reduce loneliness in New York City") 
  - `root_node_name`: Goal identifier (e.g., "Un-Lonely NYC")
  - `root_question`: Problem framing question
  - `locality`: Geographic focus area
  - `country`: National context
  - `major_theme_obstacles`: Top-level obstacle categories

#### Core GOSR Data Files
- **`o.json`**: Obstacles generated by `g2o.py` from goal and root question
- **`s.json`**: Solutions mapped to obstacles by `o2s.py`
- **`r.json`**: Hierarchical resource tree generated by `s2r.py`
- **`resources.json`**: Cleaned and normalized resources from `raw2resources.py`

#### Validation & Export Files
- **URL validation**: Enhanced by `recheck_resource_urls.py`
- **DOCX exports**: Generated by `json2doc.py` for stakeholder review
- **Mind maps**: Created by `json2mm.py` for visualization
- **Google Maps data**: Exported by `r2google-maps.py` for geographic visualization

## GOSR Principles & MCP Implementation

### Alignment Through Transparency
- **Principle**: GOSR facilitates voluntary self-organization by making problem structures visible
- **MCP Implementation**: All endpoints prioritize transparency over optimization, revealing full GOSR structure and reasoning
- **No Hidden Intelligence**: AI recommendations include rationale and alternative pathways

### Distributed vs. Centralized Coordination  
- **Principle**: Enable coordination without control through shared understanding
- **MCP Implementation**: Endpoints support multiple coordination models, defaulting to distributed approaches
- **Community Agency**: Tools empower local decision-making rather than prescribing solutions

### Evidence-Based Resource Mapping
- **Principle**: Ground abstract solutions in concrete, accessible community resources
- **MCP Implementation**: Every solution recommendation includes specific, validated resources
- **Local Context**: Geographic and cultural locality filters ensure relevance

### Continuous Learning & Adaptation
- **Principle**: GOSR frameworks should evolve based on community feedback and outcomes
- **MCP Implementation**: Advanced endpoints support framework refinement and cross-implementation learning
- **Safe-to-Fail**: Recommendations include pilot testing and iterative improvement approaches

This MCP server transforms GOSR from a static mapping exercise into a dynamic, intelligent community resilience platform that maintains the framework's core principles of transparency, distributed agency, and evidence-based action.

## Configuration

### For Claude Desktop

Add this to your `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "unsolvable-data": {
      "command": "node",
      "args": ["/path/to/your/data/mcp-server/index.js"],
      "cwd": "/path/to/your/data/mcp-server"
    }
  }
}
```

### For other MCP clients

Use stdio transport:
```bash
node /path/to/your/data/mcp-server/index.js
```

## Example Usage - MVP Implementation

```
User: What youth mental health resources are available?

LLM: I'll search the GOSR knowledge graph for youth mental health resources.

Tool Call: query_knowledge_graph
{
  "query_type": "find_resources_by_keywords",
  "keywords": ["youth", "mental health"],
  "limit": 5
}

Result: Found resources across mental-health-nova-scotia dataset including:
- Youth mental health programs
- School-based counseling services  
- Crisis intervention resources
- Community support programs

User: Tell me more about resource ID 123

LLM: Let me get the detailed information for that resource.

Tool Call: get_resource_details
{
  "resource_id": 123
}

Result: 
{
  "dataset": "mental-health-nova-scotia",
  "name": "Youth Crisis Support Program",
  "organization": "Mental Health Commission",
  "address": "123 Main St, Halifax, NS",
  "email": "support@example.org",
  "website": "https://example.org",
  "url_validated": true,
  "description": "24/7 crisis support for youth..."
}
```

## Data Structure

All datasets follow this hierarchical pattern:
```json
{
  "goal": {
    "children": [
      {
        "obstacle": {
          "children": [
            {
              "solution": {
                "children": [
                  {
                    "resource": {
                      "data": {
                        "name": "Program Name",
                        "organization": "...",
                        "description": "..."
                      }
                    }
                  }
                ]
              }
            }
          ]
        }
      }
    ]
  }
}
```
